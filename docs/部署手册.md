# AI 灵码平台部署手册

本文记录 OpenCloudOS 云服务器的最小部署流程。日常操作见[部署命令](部署命令.md)。

## 1. 准备服务器

使用有 sudo 权限的 `deploy` 账号，确认 Docker 可用：

```bash
sudo docker version
sudo docker compose version
```

应用统一使用 `sudo docker`，不要用 root 直接运行项目。

## 2. 获取代码

```bash
sudo mkdir -p /opt/ai-lingma
sudo chown -R deploy:deploy /opt/ai-lingma
cd /opt/ai-lingma
git clone <仓库地址> .
```

升级前确认没有服务器本地改动：

```bash
git status -sb
git pull --ff-only origin main
```

## 3. 配置生产环境

```bash
cp .env.production.example .env.production
chmod 600 .env.production
nano .env.production
```

必须配置数据库密码、管理员密码、域名 CORS、DeepSeek Key，以及 Qwen 视觉模型的 provider、model、base URL 和 API Key。生产建议使用：

```dotenv
AI_LINGMA_BUILD_MODE=real
AI_LINGMA_COMMAND_MODE=sandbox
AI_LINGMA_RUNTIME_UID=1002
AI_LINGMA_RUNTIME_GID=1002
```

`.env.production` 只保留在服务器，不提交 Git，不复制到聊天或截图中。

## 4. 启动服务

```bash
cd /opt/ai-lingma
sudo docker compose --env-file .env.production up -d --build
sudo docker compose --env-file .env.production ps
```

服务包括 PostgreSQL、backend 和 web。web 只绑定服务器本机 `127.0.0.1:8080`，由 Nginx 对外提供访问。

## 5. 配置域名和 Nginx

将域名解析到服务器公网 IP，在现有 Nginx 站点中代理到：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

检查并重载服务器已有 Nginx：

```bash
sudo /www/server/nginx/sbin/nginx -t -c /www/server/nginx/conf/nginx.conf
sudo /www/server/nginx/sbin/nginx -s reload -c /www/server/nginx/conf/nginx.conf
```

申请 HTTPS 后，将 `AI_LINGMA_CORS_ORIGINS` 改为 HTTPS 域名，并重新创建 backend 容器。

## 6. 验证

登录后依次验证：创建项目、生成、预览、修改、发布、首页卡片截图和质量面板“重新检查”。截图依赖 backend 镜像中的 Chromium；视觉评审依赖截图和 Qwen 配置。

## 7. 升级和备份

```bash
sudo /opt/ai-lingma/scripts/backup.sh
cd /opt/ai-lingma
git pull --ff-only origin main
sudo docker compose --env-file .env.production up -d --build
```

备份目录默认为 `/srv/ai-lingma-backups`。不要删除 PostgreSQL 卷或 `/srv/ai-lingma-data`。

## 8. 故障排查

```bash
sudo docker compose --env-file .env.production ps
sudo docker compose --env-file .env.production logs --tail=200 backend
sudo docker compose --env-file .env.production logs --tail=200 web
```

生产环境不得挂载 Docker socket，也不得把真实 API Key 写入镜像、代码仓库或日志。
